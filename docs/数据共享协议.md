# 数据共享协议 v1

参与者通过现有通讯渠道传递共享卡、申请和决定回执。链接片段或相应文件承载每份材料。收件人通过同一网站打开材料，浏览器在本地完成验证、预览和解密。发布后需要把共享卡发给目标读者，申请人也需要把生成的申请交回发布者。

| 材料 | 可见内容 | 验证方式 |
| --- | --- | --- |
| 共享卡 | 食品类别、性状名、样品数和记录数。数据说明卡列出可申请的字段名称。摘要卡显示全场每项确认记录数及均分，零条记录时均分留空 | 卡片包含发布公钥及签名。申请方本机保留收到的原卡 |
| 申请 | 用途、申请字段、申请编号、关联共享卡和申请方公钥 | 申请方对材料签名。发布者按本机保存的原卡核对申请 |
| 决定回执 | 外层含关联卡片及申请编号、回执编号、签名和加密数据 | 申请方用原卡中的发布公钥验签，再用自己的申请私钥解密 |

数据说明卡默认开放对盲码和已确认分数的申请。每次发布时，组织者可以另外勾选真实品种、田间地点、备注和个人原话。四项均默认关闭，勾选后卡片公开该字段的名称，内容保存在发布设备的私有快照中。食品类别、性状名称与申请用途来自用户输入，发送前应核对这些可见文字。

申请人逐项选定所需字段并填写用途。组织者核对申请后逐项选择批准范围，确认预览才生成回执。每条确认记录对应一行，列的顺序与预览相同。拒绝回执解密后给出拒绝状态及空表。

| 可选字段 | 私有快照中的来源 | 字符上限 |
| --- | --- | --- |
| 真实品种 `variety` | 记录盲码对应样品的 `name` | 80 |
| 田间地点 `location` | 记录盲码对应样品的 `location` | 200 |
| 备注 `note` | 当前确认记录的 `note` | 2000 |
| 个人原话 `quote` | 当前确认记录单独填写的 `quote` | 2000 |

缺失值以空字符串交付。评价员身份、评价时间、录音、语音评分转写、场次标题和模板贡献者均在明细字段范围之外。

## 发布版本与密钥

私有快照保留在发布设备。SHA-256 承诺绑定食品类别、性状、样品盲码、各记录的盲码与分数，以及发布时开放申请的可选字段及其对应文本值。输入同时包含私有随机快照编号及公开卡片编号，公开材料只持有承诺值。审批须匹配原共享卡的快照版本。未开放可选字段的卡继续使用原 v1 的承诺格式。

发布者使用 P-256 ECDSA 对共享卡与决定签名。申请方使用独立的 P-256 ECDSA 和 ECDH 密钥对。发布者每次生成回执时使用新的临时 ECDH 密钥对，通过 HKDF-SHA-256 派生 AES-256-GCM 密钥，对决定及数据表整体加密。密钥派生及附加认证数据绑定共享卡和原申请。拒绝回执采用同一加密流程。

第一次收到共享卡时，发布者的身份取决于交付渠道。签名用于验证后续材料与原卡的关联。只有一条确认记录时，公开均分等于该条记录的评分。两条记录时，已知其中一条的人可能推算另一条。以旧版发布且少于三条记录的已签名摘要卡保留原有空均分。已经交付的明文可由申请方另存，清除发布设备的记录不能收回副本。清理浏览器站点数据会丢失本机保存的密钥。链接本身不能恢复申请私钥。

## 复核

在项目根目录运行 `node --test tests/share-core.test.cjs`。测试使用独立浏览器密钥模拟三份材料的交接并核对解密内容，覆盖可选字段的三次选择、快照版本匹配、部分批准、拒绝、回执篡改、跨申请混用、文本长度、零至两条记录的摘要和历史签名卡。
